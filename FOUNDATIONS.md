# FOUNDATIONS — what each process rests on, and what changes

Audit of 2026-10-26. The user's rule: every process rests on a published method that was tested against alternatives, taking the newest work that has peer review, a public benchmark or released code (a 2026 preprint without code is a reference only); nothing rests on a developer's opinion; the app improves itself from its own data. "Same mistake" means the process rests on values or logic that a developer wrote by hand instead of on data, sources or a proven method.

## Audit

|---|---|---|---|---|---|---|
| 1 | Decision model per request | `src/research/strategy.mjs` | Glamping rules written by hand | **Yes, the worst case** | Objectives and criteria first (Keeney; Cochrane MECIR C5–C13); decision structure (DeLLMa, ICLR 2025, [arXiv 2402.02392](https://arxiv.org/abs/2402.02392)); retrieval of past experience, which the Google DeepMind Evo-Memory benchmark found competitive with complex memories, plus ReMem refinement ([arXiv 2511.20857](https://arxiv.org/abs/2511.20857)); cases ranked by measured utility (MemRL 2026, [arXiv 2601.03192](https://arxiv.org/abs/2601.03192), code released); case bank of approved runs (Memento, [arXiv 2508.16153](https://arxiv.org/abs/2508.16153)); evolving playbooks (ACE, ICLR 2026, [arXiv 2510.04618](https://arxiv.org/abs/2510.04618)) | Concept recognition per request; criteria proposed several times and kept when they agree (self-consistency, [arXiv 2203.11171](https://arxiv.org/abs/2203.11171)), their quotes are found on fetched pages and code can measure them; approved cases retrieved as examples; the glamping model stays as reference case #1 |

## Order of work

1. Routing by gate outcomes (5, done), ranking without hand weights (3), robust price outliers (15). Small, measurable, no domain logic.
2. Concept recognition, decision model per request, case bank (1, 2, 6, 12).
3. Experience store and Thompson sampling for portals and queries (4, 7).
4. Loop: Pareto frontier, reflection, demonstrations (13).

Each step: tests, the reference case (`tests/research/reference.test.ts`), a witness on a copy of a live research, a pull request, CI on Node 22 and 24, a merge.
