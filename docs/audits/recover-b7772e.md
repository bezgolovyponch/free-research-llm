## Section C. Engine lesson

No removed piece met the VALUE rule, so the lesson comes from the pieces that came closest and from what Section B showed about the table. First, D8.2.1.1.b.2 (Spain coastal land) together with spec R1 (Asturias, Canarias, Basque country; never passed) and the Vietnam pieces (D10, D15.1, D16.2, D16.3 and others, covered only by the weak D8.1.2) show that the engine treats "where to look" as a hard-coded list: `SEED_PORTALS` in src/research/portals.mjs has eight pisos.com regions without the Basque Country and no Vietnam portal at all, while the region screen in `screenCandidate` (src/research/candidates.mjs) dropped sahibinden.com pages as "outside the asked regions"; a research of this kind should derive its seed portals and region allowlist by code from the places the user names (question, constraints, specs mustMention) and report any named place that no portal covers, so that no piece has to search for listings and no asked region silently falls out. Second, D7.1.1.d (the entrance-investment breakdown, 18 supported roll-ups, lost only because its children were listing work) and the guidance "judge each plot by purchase price + preparation cost" point at `entryCost` in src/research/strategy.mjs, which still excludes "permits, platforms, water, power and furniture": a per-country preparation-cost rule (the figures D1.2 verified) would make the entry criterion a code check instead of a research piece. Third, Section B shows two code-side causes of lost plots that no piece can fix: `MAX_KEPT = 1000` and the `implausiblyLow` cut in src/research/candidates.mjs set aside 18 Portuguese plots that pass every stated criterion and are live today; the table should keep every row that passes the hard criteria (or at least never cap below the number that passed the screen) and should keep a cheap plot in the result with a "confirm the price" note rather than move it out of the result list.
