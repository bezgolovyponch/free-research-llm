# Audit A: the engine's method sources and current optimisation methods (2026-11-17)

Branch `audit/engine-2026-11-17`, base `main` ed481ad. No code was changed. Every source was looked up on 2026-11-17.

**Scope read.** `docs/specs/purpose-decomposition.md`, `data/ref/crucial-factors-spec.md` §1, `data/ref/leading-questions-spec.md` §1, `data/ref/handoff-b/specs/*.md`, `data/ref/handoff-b/HANDOFF.md` §4, `data/ref/HANDOFF-validation-2026-11-16.md` §2, `scripts/process-lessons.json`, and the method names in `src/research/*.mjs`, `src/research/*.json` and `src/llm/*.mjs` (`fundamentals.mjs`, `purpose.mjs`, `purpose.json`, `valuation.mjs`, `valueconcepts.json`, `proposal.mjs`, `valuecase.mjs`, `cci.mjs`, `strategy.mjs`, `prompts.mjs`, `embedder.mjs`).

**How each source was checked.** The "Basis" column says what was opened:

- **P** = the paper's own page was opened (arXiv abstract page, ACL Anthology, publisher or repository page).
- **X** = the bibliographic record was found in the Crossref index (`api.crossref.org/works`), which confirms authors, venue, year and pages, not the content.
- **S** = a search result summarised the page; the page itself was not opened.
- **N** = not opened in this session. These rows are not verified, and say so.

`scripts/process-lessons.json` cites no paper by author and year. Its method references (EN 12973, Ellram, Admiralty, ACH, EvalGen, MAD, embeddings) are all covered by rows below.

**Limits of this audit.** Only abstract pages were read for most papers, so a claim that sits in a paper's body is marked as such. Effects in Parts 2 and 3 are the numbers the papers report on their own tasks; none was measured on this engine.

## 2. Current methods per area

Each method lists: evidence, mapping to this engine, expected effect, effort, risk on small free models, and what to stop doing. "Fits" means: no fine-tuning, one closed judgement per call, code aggregates.

**Does not fit.** Self-RAG (arxiv.org/abs/2310.11511) trains the model to emit reflection tokens. FLARE (arxiv.org/abs/2305.06983, EMNLP 2023) triggers on low-confidence tokens, which free routes do not return. Adaptive-RAG (arxiv.org/abs/2403.14403, NAACL 2024) needs a trained complexity classifier. Corrective RAG's trigger is the part to keep, done as the T0c vote.

**Open research agents and benchmarks.** DeepResearch Bench (arxiv.org/abs/2506.11763): 100 tasks in 22 fields, scored on report quality and on citation count and accuracy. LiveResearchBench (arxiv.org/html/2510.14240v4, via search) tests 17 systems and leaves open whether several coordinating agents beat one. LocationReasoner (row 3) finds agent loops worse than direct prompting on constraint filtering. Conclusion for this engine: do not add a supervisor and worker layer; take two measurements from the benchmarks, citation accuracy and effective citations, which code can compute from quotes.

**How to find the methods and knowledge a research needs.** The engine's present answer is right in form: a `source-role` vote separates sources that explain how to judge from sources that describe a market. What is missing is a query built for method sources. Add, per requirement and market language, one query from a fixed perspective "how this is tested, graded or compared" (the same mechanism as `FIXED_VIEWS`), and count how many kept sources have role A per requirement; a requirement with none is a gap to show.

**Stop doing.** Deciding on-topic by word coverage (`topicCoverage`, row 15). Sending the opening of a page to a judge when no embedder answers; return "not judged" instead.

| **People draft, the model adds, then merge** | Simon & Siebert 2025 (row 30) | The user's clauses are the first draft; goals from the model are additions that must trace to them. This is what T2c does. Keep it | None new | None | None |

**Structure against planner prompts.** Plan-and-Solve (arxiv.org/abs/2305.04091, ACL 2023) is a prompt that plans and then solves inside one answer; its evidence is on arithmetic and reasoning sets with GPT-3. It gives nothing the T2a and T2b contracts lack, and one long answer breaks "one judgement per call". Goal-Question-Metric and KAOS give what a planner prompt cannot: a leaf rule that code checks (one checker per question) and nodes code can protect. Keep them as the structure; use the model inside each step.

**Scope before purpose, or after.** Keep the present order: requirements and one purpose draw, then scoping, then the tree. Arksey & O'Malley put "identify the question" before "identify studies"; STORM needs a topic to find perspectives; and the clarification benchmarks above put the user's intent before search. The one missing loop is from scoping back to purpose: when notes show a requirement has two readings, that is a leading question, not a silent re-draw.

**Stop doing.** Refining every goal to full depth before any item is judged. Adding agent layers to plan the research.

### Area 3 · Factor discovery and weighting

| Method | Evidence | Mapping | Effect | Effort | Risk |
|---|---|---|---|---|---|
| **A strong model writes the checklist once, a small model grades it, code reweights it** | RocketEval, ICLR 2025 (arxiv.org/abs/2503.05142): with Gemma-2-2B as grader, 0.965 correlation with human preference, more than 50 times cheaper. TICK (arxiv.org/abs/2410.03608): yes/no checklists raised exact agreement with people from 46.4% to 52.2% | This is the engine's split of deep and fast tiers. The new part is the reweighting: once the user has answered example questions ("does this listing count?"), code fits which checklist answers predict the user's yes and orders the factors by it | Factor order learned from the user's own choices; no model calls | Medium, after questions ships | Needs about 20 answered examples; below that keep the evidence order |
| **Drop redundant criteria by measured correlation** | RRD (arxiv.org/abs/2602.05125): decomposing, filtering misaligned and redundant criteria and "correlation-aware weighting" gave up to +17.7 points | Code computes, over the judged candidates, how often two factor questions give the same answer. Two factors that agree on nearly all items share one weight. No model call | Stops one underlying property from being counted twice; removes checklist questions and their judge calls | Low: one function in the planned `factorstats.mjs` | Few items make the estimate noisy; apply only at 30 or more judged items, the same floor as `pooledSlopes` |
| **Weights as a set, not one vector** | Barron & Barrett 1996 (ROC most accurate of the rank formulae); Danielson & Ekenberg 2017 and Lakmayer & Danielson 2025 (row 22) show the ranking of formulae depends on assumptions | ROC is the centroid of all weight vectors that respect the factor order. Code draws 1,000 vectors from that same set and reports, per item, how often it keeps its place. An item's rank is shown as firm only when it holds in most draws | No calls. Results stop depending on one formula | Low | None for models; the display needs one more column |

**Aspect extraction and determinant attributes.** Hu & Liu 2004 and the determinance rule of Myers & Alpert stand; the factors spec applies them correctly (a factor every candidate shares leaves the checklist). **Importance from candidate data:** the spec's rank correlation inside like items is the right simplification for small samples; state its sample floor (the spec's §4.9) in the result. **Never ask a model for a weight:** a 2026 review finds the evidence on model-made AHP weights "inconclusive" (arxiv.org/pdf/2609.16779, via search), which supports rule K2.

**Stop doing.** Nothing in the factors spec needs to stop. Do not present ROC weights as measured importance; they are a function of an order.

### Area 4 · Judgement efficiency on free models

| Method | Evidence | Mapping | Effect | Effort | Risk |
|---|---|---|---|---|---|
| **Stop voting when the outcome is settled, and start with one vote where a provider has earned it** | Adaptive-Consistency, EMNLP 2023 (arxiv.org/abs/2305.11860): up to 7.9 times fewer samples with under 0.1% average accuracy drop. Early-stopping self-consistency, ICLR 2024 (arxiv.org/abs/2401.10480): 34% to 84% fewer samples. AutoMix, NeurIPS 2024 (arxiv.org/abs/2310.12963): more than 50% lower cost with a cheap check deciding whether to escalate | `vote()` already stops at quorum 2 of 3. Next step: `recordOutcome` already stores, per provider, model and task, how often a reply agreed with the majority. When that record is long and high for a task, take one vote; send a random tenth to a full vote so the record stays honest. Votes that can veto an item always get the full vote | Up to half of fast judge calls on tasks where agreement is high | Medium: a rule in `vote()`, counts from `outcomes.mjs` | Agreement is not correctness: two models can share an error. The gold set of area 7 must confirm the record before the rule is switched on |
| **Balance option letters across votes** | Zheng et al., ICLR 2024 spotlight (arxiv.org/abs/2309.03882): the bias in multiple choice comes mainly from a prior for certain option letters, not only from position | `retrieveThenVerify` shuffles options at random per vote. Use rotations instead, so over 3 votes each option sits under 3 different letters. From the ledger, code counts each model's letter frequencies per task; a model far from even is ranked down for closed-choice tasks | Removes a systematic error at no call cost | Low | With quorum 2 only two rotations run; acceptable |
| **A small dedicated checker for "does this quote support this claim"** | MiniCheck (row 14): a 770M model at GPT-4 accuracy on its benchmark | Candidate for the meaning check of PROTOCOLS 2b and for T4d on English text, run locally | Removes model calls for those checks | High: a local model runtime in Node, and a measurement | Trained on English; the engine's pages are in several languages. Measure on the gold set first; do not adopt unmeasured |
| **Let the model reason in a short free line before the closed answer** | "Let Me Speak Freely?" (arxiv.org/abs/2408.02442): strict output formats "significantly" reduce reasoning performance | For votes that need reasoning (T2c trace, T4c subject match), compare in the replay: JSON only, against two sentences then a final line with the letter, parsed by code | Possibly better votes on the harder tasks; more output tokens | Low | Small models may not end with the letter; the validator's single retry covers it |

**Does not fit.** RouteLLM (arxiv.org/abs/2406.18665) trains its router on human preference data. Semantic caching (MeanCache, IPDPS 2025, arxiv.org/abs/2403.02694) reuses an answer when a similarity score passes a threshold, which rule R5 forbids; keep the exact cache keyed by fingerprint.

**Stop doing.** Random shuffles where rotations cost the same. Spending the same number of votes on every task whatever its measured agreement.

### Area 5 · Output structure

| Method | Evidence | Mapping | Effect | Effort | Risk |
|---|---|---|---|---|---|
| **Columns first, then values** | ArxivDIGESTables, EMNLP 2024 (arxiv.org/abs/2410.22360): table building splits into schema generation and value generation; extra context improves the schema | Table columns come from the confirmed tree: one column per determinant factor and per asked constraint, each with its checker and unit. Code keeps a column only when a value was read for enough rows, and reports the others as "not stated by the items" | Columns follow the purpose, not the portal's fields | Medium | A column few items state looks empty; show its coverage |

**Stop doing.** Deriving the shape from words in the question alone. Extracting the same field from every page of one site by a model call.

### Area 6 · Pipeline and prompt optimisation without fine-tuning

| Method | Evidence | Fit |
|---|---|---|
| **GEPA** | ICLR 2026 oral (arxiv.org/abs/2507.19457): reflects on failed runs in words, proposes prompt revisions, keeps a Pareto set; beats MIPROv2 "by over 10%" and needs up to 35 times fewer runs than reinforcement learning | Best fit: it changes instructions only and is frugal with runs, which suits daily quotas |
| **MIPROv2** | EMNLP 2024 (arxiv.org/abs/2406.11695): optimises instructions and examples of each step "without access to module-level labels or gradients"; up to 13% better with Llama-3-8B | Fits with examples switched off: examples taken from one research would put domain content in a prompt (rule R4) |
| **TextGrad** | arxiv.org/abs/2406.07496: feedback in words passed backward through the pipeline; its reported gains use GPT-4o | Weak fit: it depends on a strong model writing the feedback |

**Mapping.** Optimise offline, never in a run. The targets are the closed-vote prompts (T0c, T0e, T2c, T2e, T4c, T4d and the checklist judge). The metric is agreement with the gold labels of area 7 plus the share of valid contracts, per provider. The reflection step uses the deep tier; the candidate prompt is tested on the fast tier it will run on. A candidate is accepted only when (1) code finds no site name, domain word or research id in it, (2) it wins on the paired comparison of area 7 on questions held out from optimisation, including the counter-example questions, and (3) the quality gate passes. DSPy is a Python library; the engine needs only the loop, so a script in `scripts/` that calls the app's own router is enough.

**Effect and cost.** The papers report 10% to 13% on their tasks. Cost: each candidate is one replay of the labelled items, so budget the runs against the day's quota and run overnight. **Risk:** with three stored researches the optimiser fits those three; the held-out questions are the guard.

**Stop doing.** Changing a prompt because one replay looked better (the purpose spec already says "fixed in code, not in the prompt alone").

### Area 7 · Evaluation

| Method | Evidence | Mapping |
|---|---|---|
| **Chance-corrected agreement, not percent agreement** | Thakur et al., GEM 2025 (arxiv.org/abs/2406.12624): only the largest judges align well with people, and judges with high percent agreement can "assign vastly different scores" | The replay's "second opinion agrees ≥ 80%" is percent agreement. Report Cohen's κ per task and provider against gold labels |
| **A small gold set, and a test for when votes may replace it** | Alternative annotator test (arxiv.org/abs/2501.10970): a statistical procedure, needing "a modest subset of annotated examples", to justify a model in place of a human annotator | The owner labels 150 to 300 judgements once (item × question, source × relevance, fact × subject), drawn from the three stored researches and the counter-example questions. Every change is scored against them |
| **Valid intervals from few labels and many votes** | Prediction-powered inference (arxiv.org/abs/2301.09633): valid confidence intervals from a small labelled set plus many model predictions | Estimate the true share of correct "confirmed" items with an interval, from the gold set and all votes |
| **Error bars and paired comparisons** | Miller, "Adding Error Bars to Evals" (arxiv.org/abs/2411.00640): formulas for comparing two systems and planning the sample; its paired and clustered recommendations are in the body, not seen on the abstract page | A change is compared with its baseline on the same items; the difference gets a bootstrap interval, resampled by research. The loop already demands two measurements above noise; apply the same rule to replays |
| **A fixed page corpus for replays** | BrowseComp-Plus (arxiv.org/abs/2508.06600): a fixed corpus makes agent comparisons "fair and transparent" | Replays read stored pages, so a change in search results cannot look like a change in logic. `purpose-replay.mjs --projects` is halfway there |
| **Known judge biases** | CALM (arxiv.org/abs/2410.02736) quantifies 12 biases; self-preference (row 59) | Keep votes on different providers than the author; add the letter-prior check of area 4 |

**Replay targets.** Keep the purpose spec's by-construction targets (quotes on the page, no grade from a model). Change three: (1) agreement targets become κ against gold; (2) every target that is a rate carries its count and interval; (3) each replay runs three times, as the `flakes` gate does for tests, because free routes answer differently run to run. Add from the research benchmarks: citation accuracy and effective citations per result, computed by code.

**Stop doing.** Merging on one replay table (handoff-b §5 already records this failure for #190). Reading percent agreement as reliability.
