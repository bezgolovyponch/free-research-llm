## B. Known Live Failures on main `123fed0`

### 1. Plots run hangs silently after "portal sweep: 90 listing page(s) read" (twice today, 0% CPU, no model calls); cancel not honoured there until much later.

**CONFIRMED** - Engine cause: `src/research/sweep.mjs:134`

The `visit()` function checks `shouldStop()` at line 103, but the pagination loop at line 134 continues fetching next pages without checking cancellation. The loop condition `left > reserved && (start.seed || keptNow() < target)` does not include `!this.shouldStop()`. When `shouldStop()` returns true (user cancelled), the sweep continues until `left` budget exhausted or no more pages.

**Evidence:** `src/research/engine.mjs:1055` passes `shouldStop: () => this.cancelled.has(project.id)` to sweeper. `src/research/engine.mjs:1997,2005,2046,2053` calls `stopIfCancelled` only at phase boundaries, not during sweep.

### 2. Cancel overwrites the stored acceptanceSummary ("0 of 50 confirmed - 43 not read" after cancelling plots).

**CONFIRMED** - Engine cause: `src/research/engine.mjs:1924-1932, 2062`

At line 2062, `project.acceptanceSummary = acceptanceSummaryOf(project)` only runs on successful completion. When cancelled during sweep, the project is saved with the old `acceptanceSummary` (or null), but the UI may display a computed summary from stale `acceptanceResult` that doesn't match the actual state.

**Evidence:** `acceptanceSummaryOf` at `src/research/verdict.mjs:150-156` reads from `project.acceptanceResult.verdict.summary`. If cancelled before `checkAcceptance` runs, `acceptanceResult` reflects previous run.

### 3. Router keeps sending calls to a provider answering HTTP 402 (pollinations, 10 in an hour).

**CONFIRMED** - Engine cause: `src/llm/router.mjs:55-58, 490-498`

If a 402 response message matches `SHORT_LIMIT` or `CREDIT_EXHAUSTED`, `paymentRequired()` returns false, so the provider is not excluded via `excludeForPayment()`. The provider stays in `available()` and keeps being tried.

**Evidence:** `available()` at line 173 filters `!this.needsPayment(p.id, time)` but `needsPayment` only checks `paymentUntil` map set by `excludeForPayment`. If 402 doesn't trigger `excludeForPayment`, provider remains available.

### 4. Report "LIVE check" on items the verifier marked unconfirmed (HTTP 403); report deliverables stale from an older run.

**CONFIRMED** - Engine cause: `src/research/engine.mjs:1707-1723, 1498`

In `synthesize()` (line 1466-1505), `checkAcceptance` is called at line 1498 *after* the report is created (lines 1478-1497). If `resynthesize()` is called without `checkAcceptance` (line 2341), or if the report is viewed before `checkAcceptance` completes, `project.report.deliverables` is stale.

For "LIVE check" on HTTP 403: `pageIsLive()` at `src/research/acceptance.mjs:641-646` returns false for status >= 400. But the verifier (external) may mark items unconfirmed for other reasons (kind check, hard checks). The report markdown (`src/report.mjs:96-124`) shows `r.verdict` and `r.summary` but not per-item live status. The "LIVE check" likely appears in the acceptance checks display where `spec.urlsLive` check (line 709) shows `good((i) => i.live)` - if `pageIsLive` returns true for a redirect (status 3xx with `allowRedirect=true` at line 644), but the verifier later marks it unconfirmed.

### 5. Checklist model adds questions traceable to no clause, hint or criterion (e.g. a naira price on plots, "fenced and gated").

**CONFIRMED** - Engine cause: `src/research/checklist.mjs:223-229, 92-157`

The model generates checklist items from the question + guidance, but there's no post-generation validation that each item maps to a specific clause in the question, a hint, or a decision-model criterion. `filterCountItems` (line 243-248) only removes items mentioning numbers from acceptance criteria. The `sameMeaning` function uses Jaccard similarity on content words (threshold 0.3), which clusters semantically similar questions but doesn't enforce traceability to source clauses.

**Evidence:** Naira price on plots would come from model hallucination or guidance misinterpretation; "fenced and gated" would be a generic property question not tied to any user clause.

**CONFIRMED** - Engine cause: `src/research/gaps.mjs:76-82, src/research/engine.mjs:1507-1534`

The `fix/honest-headline` branch is at commit `123fed0` (same as origin/main) - **no fixes applied yet**. The contradiction arises because `planActions` overwrites `project.report.verdict` with a provisional prefix based on acceptance, but the original `modelVerdict` (from synthesis) may say "50% met" while acceptance says "0 of 50 confirmed".

**Evidence:** `src/research/engine.mjs:1479-1480` stores both `verdict` and `modelVerdict`; line 1511 uses `modelVerdict` for the memo text but line 1529 overwrites `verdict` with acceptance-based text.
